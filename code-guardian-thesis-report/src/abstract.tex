Static analysis tools miss issues that need contextual reasoning, while cloud Large Language Models (LLMs) introduce privacy risks because source code leaves the device. This thesis combines local LLMs with Retrieval-Augmented Generation (RAG) in a VS Code extension that detects and repairs vulnerabilities entirely on the developer's machine, using locally stored CWE, CVE, and OWASP knowledge.

The system is evaluated on 101 JavaScript/TypeScript cases (71 vulnerable, 30 secure) over three runs per sample, measuring precision, recall, F1, sample-level secure-FPR, latency, and an auto-applicable repair rate. The best configuration, \texttt{qwen3:8b} with RAG, reaches F1 71.43\%, precision 72.46\%, recall 70.42\%, FPR 10.00\%, and stage-1 median latency 2\,216\,ms under canonical-taxonomy matching. An inter-run confidence gate at $\geq 2/3$ agreement lifts precision to 78.13\% (F1 74.07\%) at unchanged recall and FPR; on a held-out 30-case test split the same threshold yields F1 63.16\%, precision 70.59\%, and FPR 0\%, confirming the threshold was not overfit to the evaluation set. Repair runs as a stage-2 call per finding, returning a structured \texttt{\{code, language\}} object; the auto-applicable rate is 90.32\,\% (252/279), with the residual concentrated in mid-statement truncations and unterminated regular-expression literals rather than prose. RAG is sharply model-dependent: it lifts \texttt{qwen3:8b} but degrades \texttt{codellama+RAG} by about 30 F1 points (the only effect surviving Bonferroni correction across the five tested models), so retrieval augmentation must be calibrated per model.

Overall, local privacy-preserving LLM workflows can support useful vulnerability detection and structured repair generation at interactive latency on consumer hardware. A held-out 70/30 threshold validation, an automated egress-and-leak harness, and signed-corpus integrity verification anchor the privacy and reproducibility claims.
