This chapter presents the conceptual design of Code Guardian, a VS Code extension for local vulnerability detection and repair in JavaScript/TypeScript projects. The design derives from two observations in the preceding analysis. First, no existing tool simultaneously offers contextual reasoning, repair guidance, and source-code privacy. Second, the requirements from Chapter~\ref{chap:analysis} impose concrete constraints on how such a tool must be built --- particularly around output stability (R2), response latency (R4), and the guarantee that code never leaves the machine (R5).

The chapter develops the design from the outside in. It first traces how each architectural decision answers the gaps and requirements identified in the previous chapter (Section~\ref{sec:concept-derivation}), then names the components that carry out that design (Section~\ref{sec:system-components}), and shows how those components are orchestrated into the detection and repair workflows that the user actually sees (Section~\ref{sec:detection-strategies}). The chapter closes with the C4 views and sequence diagrams (Section~\ref{sec:system-architecture}) that make one boundary explicit above all others: source code stays on the developer's machine.
