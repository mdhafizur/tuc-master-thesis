\paragraph{Key findings.}
The headline configuration \texttt{qwen3:8b+RAG} reaches canonical F1 71.43\% / precision 72.46\% / recall 70.42\% / FPR 10.00\% with stage-1 detection median 2\,216\,ms; with the inter-run confidence gate at $\geq 0.67$ precision rises to 78.13\% (F1 74.07\%) at unchanged FPR. The two-stage pipeline issues a separate stage-2 repair call per detected finding (median 3\,320\,ms per fix) using a structured \texttt{\{code, language\}} schema; this is the cost paid only when a quick-fix is generated. RAG is sharply model-dependent: it lifts \texttt{qwen3:8b} (F1 $+3.91$, precision $+10.83$, FPR $50\%\!\to\!10\%$), is roughly neutral on \texttt{gemma3}, slightly degrades \texttt{qwen3:4b} ($-5.22$ F1), and severely degrades \texttt{codellama} ($-29.89$ F1, latency nearly doubles), so it must be calibrated per model rather than enabled by default. The remaining LLM configurations still flag every secure sample at least once, so the confidence gate alone is insufficient for them. Semgrep complements the LLM with very low FPR (6.67\%) and 63\,ms median latency at the cost of low recall (12.68\% canonical); the hybrid SAST-fusion option promotes LLM findings corroborated by Semgrep on overlapping line range and matching canonical category to confidence~$1.0$. The auto-applicable repair rate is 90.32\,\% (252/279) from the structured stage-2 repair pipeline; the residual 10\,\% is mid-statement truncation or unterminated regex literals in real code rather than prose (Section~\ref{sec:eval-r3-auto-applicable}). Both manual review (68\,\% on $n=25$) and the deterministic auto-applicable bar are reported. Privacy is fully preserved: all analysis runs locally with no source-code transmission.

Specific point estimates --- detection metrics (Sections~\ref{sec:eval-r1}, \ref{sec:eval-r1-confidence}), auto-applicable repair rate (Section~\ref{sec:eval-r3-auto-applicable}), stage-split latency (Section~\ref{sec:eval-metrics}), and reproducibility (Section~\ref{sec:eval-reproducibility-metric}) --- are presented in the corresponding requirement sections rather than duplicated here. Limitations and threats to validity are taken up in the Discussion that follows.
