\chapter{Evaluation Details}
\label{appendix:eval-details}

This appendix documents the evaluation dataset composition, run configuration, and per-case schema beyond what fits in the evaluation chapter.

\section{Curated Test Suite Overview}
\label{app:dataset-overview}

The curated evaluation suite contains JavaScript/TypeScript vulnerability snippets with expected CWE/severity metadata.

\subsection*{Dataset sizes}

For the scored thesis run in Chapter~\ref{chap:evaluation}, the harness uses:
\begin{itemize}
  \item \textbf{Primary vulnerable set:} \texttt{vulnerability-test-cases.generated.json} with 71 vulnerable cases
  \item \textbf{Secure overlay set:} \texttt{negatives-only.generated.json} with 30 secure/negative cases
\end{itemize}
Thesis tables are derived from merged run artifacts (effective 101-case set: 71 vulnerable + 30 secure).

\subsection*{Representative Vulnerability Classes}

Included classes (non-exhaustive):
\begin{itemize}
  \item SQL injection (CWE-89)
  \item Cross-site scripting (CWE-79)
  \item Command injection (CWE-78)
  \item Path traversal (CWE-22)
  \item Insecure randomness (CWE-338)
  \item Hardcoded credentials (CWE-798)
  \item CSRF and authentication-flow weaknesses (CWE-352, CWE-287)
  \item Prototype pollution / unsafe reflection patterns (CWE-1321, CWE-470)
\end{itemize}

\subsection*{Test Case Record Format}

Each test case includes:
\begin{itemize}
  \item a code snippet (\texttt{code}),
  \item a list of expected findings (\texttt{expectedVulnerabilities}),
  \item optional remediation guidance (\texttt{expectedFix}).
\end{itemize}

\subsection*{Reproducing the harness run}

The evaluation script is executed locally:
\begin{lstlisting}[language=Java, caption={Running the evaluation script}, label={lst:appendix-eval-run}]
cd code-guardian-extension
node evaluation/evaluate-models.js --ablation --include-baselines \
  --dataset=datasets/vulnerability-test-cases.generated.json --runs=3 --rag-k=5 --temperature=0 \
  --num-predict=1000 --timeout-ms=30000 --delay-ms=500
node evaluation/evaluate-models.js --ablation --include-baselines \
  --dataset=datasets/negatives-only.generated.json --runs=1 --rag-k=5 --temperature=0 \
  --num-predict=1000 --timeout-ms=30000 --delay-ms=500
\end{lstlisting}

The script reports per-model precision/recall/F1, FPR, latency, and parse success.

\subsection*{Merged Baseline Snapshot}

From the merged artifact (\texttt{71 vulnerable + 30 secure}), under canonical-taxonomy matching (Section~\ref{sec:eval-metrics}) the SAST baselines measured:
\begin{itemize}
  \item \texttt{semgrep}: Precision 50.00\%, Recall 12.68\%, F1 20.22\%, FPR 6.67\%
  \item \texttt{codeql}: Precision 12.07\%, Recall 9.86\%, F1 10.85\%, FPR 53.33\%
  \item \texttt{eslint-security}: Precision ---, Recall 0.00\%, F1 0.00\%, FPR 0.00\%
\end{itemize}

Baselines run on a temporary snippet workspace. Semgrep uses \path{p/security-audit}, \path{p/javascript}, \path{p/typescript}, and \path{p/owasp-top-ten}; CodeQL uses \path{javascript-security-and-quality}; ESLint uses \path{eslint-plugin-security}. Findings are normalized into the harness schema via heuristic type inference, so category-level comparisons should be interpreted as approximate.

\subsection*{Artifact Checklist}

For reproducibility, archive:
\begin{itemize}
  \item Raw run output JSON from the harness (all configurations and per-case results)
  \item Exact run configuration object (models, prompt modes, runtime parameters)
  \item Model digests / quantization metadata used for inference
  \item Environment metadata (OS, Node.js, Ollama versions, hardware)
  \item scripts/tables used to derive reported descriptive metrics
\end{itemize}

The full dataset is machine-readable in the repository.
