This chapter describes how Code Guardian was implemented as a VS Code extension, translating the conceptual design from Chapter~\ref{chap:concept} into a deployable system. The focus is on practical engineering decisions that affect reproducibility, latency, and privacy preservation on developer hardware: local inference boundaries, deterministic output handling, latency guardrails, and developer-controlled remediation.

The chapter narrows from the runtime substrate inwards. The technology stack and runtime boundary fix the locality envelope and the deterministic-decoding contract on which every later mechanism rests. The detection pipeline then operationalizes that envelope as a two-stage detect-then-repair flow with explicit latency gates and an audit-mode AST hybrid for whole-project scans. The core components --- analyzer, RAG manager, cache, workspace scanner --- compose this pipeline into the developer's editing loop, while the user-facing layer (diagnostics, quick-fix actions, dashboards, contextual Q\&A) shapes how findings reach the reader. Repair safety closes the chapter by documenting the syntactic-applicability bar on every generated fix and the developer-controlled apply-or-discard surface; the privacy-enforcement section then ties the runtime egress policy and signed corpus back to the threat model named in Chapter~\ref{chap:analysis}.

\section{Implementation Summary}

The implementation realizes the thesis architecture as a local IDE assistant whose engineering choices map directly onto the requirements derived in Chapter~\ref{chap:analysis}. The two-stage detection-then-repair pipeline with JSON-mode decoding and structured-output schemas supports R1 by making findings machine-checkable and R3 by separating the repair contract from the detection contract. Function-level scoping with debounced triggering and an LRU cache supports R4 by holding inline analysis inside the interactive latency budget; the audit-mode AST + LLM hybrid extends the same backend to whole-project scans without inflating the inline path. The synchronous egress gate and Ed25519-signed corpus support R5 by closing both the source-exfiltration and retrieval-poisoning arms of the threat model. Multi-pass consensus with inter-run confidence supports R2 by surfacing reliability without relying on a single sample, and the syntactic auto-applicability check on every generated fix supports R3 with a deterministic, fleet-wide quality bar. Together these mechanisms provide the substrate that the next chapter measures.
